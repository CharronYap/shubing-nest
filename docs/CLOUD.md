# 雲端帳號

小窩用自己的 Firebase 專案 `shubing-nest`，帳號和好友只在小窩裡，不跟薯餅蛋蛋島共用。只有幣跟蛋蛋島共用：錢包放在蛋蛋島的專案 `plush-crush`，小窩用同一組名字和密碼登入蛋蛋島的帳號去讀寫（`docs/WALLET.md`）。

| 放什麼 | 位置 |
| --- | --- |
| 帳號（名字＋密碼） | Authentication |
| 好友碼、名字、好友名單 | Firestore `players/{uid}` |
| 小窩的存檔 | Firestore `nestSaves/{uid}` |
| 給朋友看的房間（去朋友家） | Firestore `nestRooms/{uid}` |
| 朋友留的愛心 | Firestore `nestRooms/{uid}/hearts/{日子}_{送的人}` |
| 送給朋友、還在門口等的娃娃 | Firestore `nestGifts/{自動編號}` |
| 訪客簿（第五版） | Firestore `nestRooms/{uid}/book/{日子}_{寫的人}` |
| 朋友幫忙澆的水（第五版） | Firestore `nestRooms/{uid}/water/{日子}_{澆的人}` |
| 躲貓貓：朋友找的結果 | Firestore `nestRooms/{uid}/found/{日子}_{找的人}`；躲在哪裡放在公開房間 `nestRooms/{uid}` 的 `hide` |
| 去朋友家過夜的娃娃（第五版） | Firestore `nestStays/{出門的人}` |
| 明信片（第五版） | Firestore `nestCards/{自動編號}` |

## Firebase 後台（2026-11-26 已經設好）

都在 https://console.firebase.google.com 的 `shubing-nest` 專案裡，下面這些已經做完，不用再動：

- 「Authentication」→「登入方式」：開了「電子郵件／密碼」。玩家只取名字，程式會把名字換成 `名字@players.shubing-nest.firebaseapp.com` 這種不會收信的地址。
- 「Authentication」→「設定」→「授權網域」：加了 `charronyap.github.io`。
- 「Firestore Database」：資料庫 `(default)`，位置 asia-southeast1。
- 「Firestore Database」→「規則」：發布的是這個 repo 的 `firestore.rules`。

`firestore.rules` 前面 `saves`、`players` 兩段是從蛋蛋島的規則原樣複製來的，小窩用 `players`（好友）和最後一段 `nestSaves`（存檔），`saves` 用不到。`nestSaves` 已經留好第二版的四個欄位（`album`、`away`、`look`、`closet`），第四版再加三個（`season`、`mail`、`yard`）。

之後改了 `firestore.rules`，要再到「Firestore Database」→「規則」，把編輯框整份換成新的內容，按「發布」。沒發布的話，存檔裡有新欄位時雲端會拒絕，畫面會跳出「雲端存檔還沒開好」，進度先存在這台裝置。

### 2026-11-26 新增（已發布）：去朋友家和愛心

`firestore.rules` 多了兩段，2026-11-26 已經跟第四版的改動一起整份發布。

- `match /nestRooms/{uid}`：公開房間。登入的人都能讀；只有本人能寫，而且只能有 `name`（1～24 字）、`home`（`living`、`bed`、`bath` 三間，每間的檢查跟存檔一樣）、`look`（娃娃穿什麼）、`t` 這幾個欄位。存檔裡的幣、道具、相簿都不會放進來。
- `match /nestRooms/{uid}/hearts/{hid}`：愛心。文件名字是 `日子_送的人uid`，日子是台灣時間從 1970 年起算的第幾天，所以同一個人一天只能有一份。
  - 只有好友能送：送的人和房間主人，其中一方的 `players` 好友名單裡要有對方。
  - 只能送給別人、只能寫 `from`（自己）和 `day`（今天）兩個欄位，日子要跟伺服器時間對得上，不能補送昨天或預送明天。
  - 送出去就不能改、不能刪。
  - 房間主人可以數自己收到幾顆；送的人只能確認自己今天那一份在不在，讀不到別人送的。

如果主控台上的規則被換回舊版，登入的人照常玩，只是：自己的房間放不上去、點朋友會跳「朋友的房間現在還看不到」、帳號視窗不會出現「今天收到幾顆愛心」。程式不會報錯，也不影響存檔。

這兩段沒有在模擬器跑過，可以用兩個帳號在線上試一次：兩個帳號互加好友、各打開一次小窩、互相去對方家留愛心，再試第二次留愛心應該被擋。

### 2026-11-26 第四版新增（已發布）：存檔新欄位和送娃娃

跟上面那兩段一起，2026-11-26 整份發布。

- `nestSaves` 的白名單多了 `season`（今年送過的節日東西）、`mail`（信箱）、`yard`（門外小島），檢查方式跟第二版的四個欄位一樣：可有可無，是 map 或 list，200 項以內。
- `match /nestGifts/{gid}`：送娃娃。一份文件是一隻在朋友門口等的娃娃。
  - 只能用自己的名義寄（`from` 一定是本人），不能寄給自己，收的人要是好友（任一邊的 `players` 好友名單裡有對方就算）。
  - 欄位只能有 `from`、`fromName`（1～24 字）、`to`、`toName`（24 字以內）、`doll`（20 字以內）、`line`（0～5，第幾句話）、`t`（寄出時間）。
  - 寄的人和收的人都讀得到、都能刪：收的人按「讓牠進來」、寄的人按「收回」都是刪掉這份。寄出之後不能改。
  - 讀一份已經不在的（對方剛領走或收回）會讀到「不存在」，不會被規則擋，畫面才能說「朋友已經讓牠進門了」或「朋友收回去了」。
  - 一天送幾次、門口最多幾隻，只在遊戲畫面上擋，規則不檢查。

規則沒收這些欄位時（例如被換回舊版），存檔會先拿掉 `season`、`mail`、`yard` 再存，其他進度照常上雲端（換到別台裝置時，信箱和小島不會跟過去）；按「送出」會跳「雲端還沒開好送娃娃（規則還沒發布），先不能送」，娃娃不會被扣。

這段也沒有在模擬器跑過，可以用兩個帳號在線上試：兩個帳號互加好友，A 送一隻給 B，B 的信箱要看到；A 收回，B 那邊按「讓牠進來」要顯示朋友收回去了；再送一次，B 讓牠進來，A 的「在朋友門口等的」要消失。也可以試寄給不是好友的人，應該被擋。

換網址（例如綁自己的網域）時，要把新網址加進授權網域，不然登入會顯示「這個網址還不能登入」。

### 2026-11-26 第五版新增（已發布）：訪客簿、願望清單、澆水、過夜、明信片

`firestore.rules` 這次的改動已經在 2026-11-26 整份發布（五項加下面的賺幣和新房間，一次發布）。

這版開放自己打字，規則裡每個打字的欄位都檢查是文字、有長度上限（訪客簿、小紙條、送娃娃 40 字，明信片 80 字），而且要**收的人自己的 `players` 好友名單裡有寫的人**才寫得進去（訪客簿、明信片、送娃娃的 `msg`）。好友名單是每個人自己寫自己的，如果只看「任一邊加了對方」，陌生人把你加進他的名單就能寫字給你；看收的人的名單，把對方移除他就寫不進來。愛心、澆水、過夜、只選寫好句子的送娃娃照舊任一邊加了就算。規則沒辦法看字的內容，所以沒有髒話過濾，靠刪除和移除朋友處理。畫面上這些字一律用 `textContent` 顯示（`js/social.js` 的 `txSlot`），不會被當成網頁內容。

- `nestRooms/{uid}` 公開資料多兩欄：`want`（願望清單，list，最多 3 個）、`yard`（小島 12 塊地現在的樣子，`{p: [12 個]}`）。
- `match /nestRooms/{uid}/book/{bid}`：訪客簿。主人自己加過的好友才能寫、才讀得到（寫的人另外能讀自己那一則），不能寫在自己家；文件名字是 `日子_寫的人uid`，日子要是今天，所以一人一天一則。欄位：`from`、`fromName`、`day`、`sticker`、`msg`（可以不填）。主人能刪任何一則，寫的人能刪自己的；不能改。
- `match /nestRooms/{uid}/water/{wid}`：幫忙澆水。主人的朋友才能寫，一人一天一次，`plot` 是 0～11。主人讀得到全部、能刪；澆的人只能確認自己今天那一筆在不在。
- `match /nestStays/{sid}`：過夜。文件名字是出門的人的 uid，所以一次只能有一隻在外面。出門的人建立（`to` 要是朋友、`day` 要是今天、`note` 要是空的）；主人只能改 `note`（40 字以內）、`x`、`y`；兩邊都讀得到、都能刪（出門的人刪 = 回家，主人刪 = 送牠回家）。
- `match /nestCards/{cid}`：明信片。寄的人是本人、收的人的好友名單裡要有寄的人；`snap` 是那間房間的擺法，房間的部分跟公開房間用同一個檢查；`msg` 80 字以內。兩邊能讀、能刪，不能改。
- `nestGifts` 多一欄 `msg`（自己打的一句話，可以不填，40 字以內）。有 `msg` 時收的人的好友名單裡要有寄的人；沒有 `msg` 照舊任一邊加了就可以。
- 一天寄幾張明信片、一天收幾個朋友的澆水、家裡最多幾隻客人，只在遊戲畫面上擋，規則不檢查。

如果主控台上的規則被換回舊版，登入的人照常玩，用到新集合的地方都不會跳錯誤：

- 公開房間：程式會先拿掉 `want`、`yard` 再寫，去朋友家照舊能用；朋友看不到願望木牌和小島鈕。
- 訪客簿打開會寫「訪客簿現在打不開，晚點再試」。
- 過夜、明信片按下去會跳一句「雲端還沒開好這個功能，晚點再試」，娃娃不會出門、次數不會扣。
- 送娃娃自己寫的那句送不出去，畫面會說把字清掉、用快速選的就可以送。

這幾段沒有在模擬器跑過，也還沒用兩個真帳號試過。可以用兩個帳號互加好友試一輪：在對方的訪客簿留言（同一天第二則應該被擋）、幫對方澆水、讓娃娃過夜再由對方塞紙條、寄一張明信片、送娃娃時自己寫一句。也可以試不是好友的帳號，應該全部被擋。

## 玩起來是怎樣

- 沒登入也能玩，進度存在這台裝置（訪客存檔）。封面左上角的「登入」按鈕可以登入或開新帳號。
- 登入時，帳號裡還沒有小窩，這台的進度會直接搬進帳號。帳號裡已經有小窩、這台又玩過，會問要不要帶進去：房間擺設用帳號裡的，娃娃、家具、壁紙、道具和幣取兩邊比較多的。
- 登入後每次改動，等 1.5 秒存一次到雲端。封面帳號按鈕旁邊的小圓點：綠色＝已經存到雲端，黃色＝存檔中，橘色＝離線或雲端還沒開好（連上後會自動補存）。
- 打開遊戲時，雲端那份是別台裝置後來存的，會換成雲端那份。玩到一半發現別台裝置改過，也會換成最新的，不會拿舊的蓋掉。
- 登出後回到這台裝置的訪客存檔。
- 帳號按鈕裡可以看自己的好友碼、輸入朋友的好友碼加好友。對方輸入你的好友碼後，也會出現在你的名單裡。
- 每次雲端存檔成功，會順便把三個房間的擺設、娃娃的衣服和名字放到 `nestRooms/{uid}` 給朋友看（內容沒變就不重寫）。
- 好友清單點朋友的名字，會進到朋友家：只能看，點娃娃冒愛心，下面可以留一顆愛心。一天一顆，按過就變灰。
- 帳號視窗的好友碼下面會寫「今天收到 n 顆愛心」，0 顆不出現。不顯示是誰送的。
- 信箱下面的「送娃娃給朋友」只有登入後才出現。朋友送來的娃娃排在信箱最上面；打開小窩、切回這個分頁、每 5 分鐘各看一次有沒有新的，不是即時的。

## 本機測試

用 Firebase 模擬器測，不會碰到真的帳號和存檔。需要 Node.js 和 Java（Firestore 模擬器要用）。

```bash
npx firebase-tools emulators:start --project demo-plush
```

另開一個終端機跑網頁：

```bash
python3 -m http.server 8765
```

瀏覽器打開 http://localhost:8765/?emu=1 。網址有 `?emu=1`、而且是在 localhost 打開時，才會連模擬器的假專案 `demo-plush`。

## 關掉雲端帳號

把 `js/cloud-config.js` 的 `FIREBASE_CONFIG` 換成 `null`，封面就不會出現帳號按鈕，所有人都只用這台裝置的存檔。

### 2026-11-26 躲貓貓新增（已發布）：公開房間的 hide 和 found

2026-11-26 下午 4:36 整份發布，線上的內容跟這個 repo 的 `firestore.rules` 一樣。

- 公開房間 `nestRooms/{uid}` 多一欄 `hide` = `{d, r, f, day}`（哪一隻、哪一間、家具的編號、哪天躲的），可有可無；`d`、`r` 是 1～12 字的文字，`f`、`day` 是整數。
- `match /nestRooms/{uid}/found/{fid}`：朋友來找的結果，寫法跟澆水一樣。主人的朋友才能寫、不能寫在自己家，一人一天一筆、不能改；`ok` 是布林、`n` 是 1～3 的整數。主人讀得到全部、能刪；找的人只能確認自己今天那一筆在不在。
- 一天 3 次機會只在遊戲畫面上擋，規則只檢查 `n` 的範圍。躲在哪裡放在公開資料裡，懂程式的人看得到答案，兩個人玩不防這個。
- 兩個人的紀念冊、今天誰來過存在自己存檔的 `album` 裡，沒有改規則。

這一段沒有在模擬器跑過，也還沒用兩個真帳號試過。

### 2026-11-26 事故：雲端存檔從某一刻開始一直寫不上去

- **原因**：`js/gift.js` 把娃娃送的小禮物記成 `[[日期, 字, 種類]]`，陣列裡面直接放陣列。Firestore 不收這種形狀（`Nested arrays are not supported`），所以只要有一隻娃娃送過一次小禮物，之後每一次雲端存檔都整份失敗；當時只在 console 留一行，畫面上還顯示成「離線中」。
- **後果**：明信片、送來的娃娃、過夜回家這幾樣是「抄進自己的存檔就刪雲端那一筆」。存檔沒上雲端，雲端那筆又刪了，東西就只剩在那一台裝置上；換一台裝置、換瀏覽器（Safari 和加到主畫面的是分開的）、重新登入，都只看得到雲端那份舊的。
- **改了什麼**：
  - 小禮物改成一筆一個物件 `{t, s, k}`，舊存檔打開時自動轉。
  - 存檔送出前檢查一次（`js/account.js` 的 `checkSave`）：陣列包陣列、規則不收的欄位和型別，都印出是哪個路徑。在 console 打 `nestNet.check()` 可以看。
  - 領東西改成「自己的存檔寫上雲端之後」才刪雲端那一筆（`js/social.js` 的 `sAfterSave`）。
  - 這台有還沒傳的進度、雲端又被別台改過時，改成合併（以雲端為底，這台領到的東西留著），不再整份換掉；登出或登入過期後再登入，這台留著的進度會接回來。
  - 存檔連續失敗兩次：封面的帳號鈕變紅點、遊戲裡「回封面」的鈕上亮驚嘆號、跳一句提示，帳號視窗裡寫原因；之後每 15 秒到 2 分鐘自己再試。
- **以後加存檔欄位要注意**：清單裡的每一筆用物件，不要用陣列；最上層不能加新欄位（規則有白名單），放在 `album`、`mail`、`earn` 這些現有的欄位裡面。
